## 1. Supabase 운영 프로젝트
1. 대시보드에서 새 프로젝트 생성: 조직 `Victor-wonderful's Org`, 이름 `fortuna-admin`, 리전 `ap-northeast-2`(Fortuna 앱 프로젝트와 동일). DB 비밀번호는 Victor 가 직접 정하고 비밀번호 관리자에 보관.
2. 터미널(D:\admin)에서 연결·마이그레이션:
   ```bash
   npx supabase link --project-ref <새 프로젝트 ref>
   npx supabase db push
   ```
   0001~0050 이 순서대로 적용된다. `extensions.crypt`/`gen_salt` 는 Supabase 기본 `pgcrypto` 를 쓰므로 별도 설정 없음.
3. 운영 초기 데이터(1회) — 상품 4종 + 회사 루트 파트너 + 초대 코드. **seed.sql 은 절대 넣지 않는다.**
   Supabase 대시보드 → SQL Editor → New query → `supabase/prod_bootstrap.sql` 전체를 붙여넣기 →
   상단 "▼ 여기 세 값만 바꾼다" 의 이메일·이름·비밀번호를 실제 값으로 고친 뒤 Run.
   (예시값을 안 바꾸면 스크립트가 스스로 중단한다.) 마지막 결과의 `referral_code` 를 기록한다.
   가입 안내 링크는 `https://<포털 도메인>/signup?ref=<코드>`.
4. 값 확보: Settings → API 에서 `Project URL`, `service_role` 키.

## 2. Vercel
1. Vercel 대시보드 → Add New → Project → GitHub `Victor-wonderful/admin` Import (팀 `Victor's projects`). Framework 는 Next.js 자동 인식.
2. 환경변수(Production). 값은 Victor 가 대시보드에 직접 입력한다.

   | 이름 | 값 | 비고 |
   |---|---|---|
   | `SUPABASE_URL` | 새 프로젝트 URL | 서버 전용 |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role 키 | 서버 전용, 절대 NEXT_PUBLIC 아님 |
   | `NEXT_PUBLIC_SUPABASE_URL` | 새 프로젝트 URL | |
   | `FORTUNA_SUPABASE_URL` | Fortuna 앱 프로젝트 URL | `.env.local` 값 그대로 |
   | `FORTUNA_SUPABASE_SERVICE_ROLE_KEY` | Fortuna 앱 service_role | `.env.local` 값 그대로 |
   | `CRON_SECRET` | 32자 이상 무작위 문자열 | Vercel Cron 이 Bearer 로 자동 첨부 |
   | `RESEND_API_KEY` | Resend 키 | 비밀번호 재설정 메일 |
   | `NOTIFY_FROM_EMAIL` | `Fortuna <no-reply@인증도메인>` | |
   | `ADMIN_BASE_URL` | `https://<관리자 도메인>` | 관리자 재설정 링크 |
   | `PORTAL_BASE_URL` | `https://<포털 도메인>` | 회원 재설정 링크 |
   | `NEXT_PUBLIC_KAKAO_JS_KEY` | (선택) | 카카오 공유 |
   | `COMPANY_DEPOSIT_ADDRESS_TRC20` / `_BEP20`, `TRONGRID_API_KEY`, `BSCSCAN_API_KEY` | **비움** | 3단계에서 채움 |
   | `ADMIN_MFA` | **넣지 않는다** | 개발용 off 스위치. 운영은 MFA 항상 켜짐 |

3. Deploy. `vercel.json` 의 크론 2개가 자동 등록된다(renewals 매일 00:10 UTC = 09:10 KST, deposits 5분).
4. 도메인 연결(관리자·포털이 한 앱이면 도메인 1개, 경로로 구분). 연결 후 `ADMIN_BASE_URL`/`PORTAL_BASE_URL` 을 실제 도메인으로 맞추고 재배포.

## 3. 배포 직후 점검(회원 공개 전 필수)
1. `/admin-login` → 데모 관리자 `admin@fortuna.demo` / `admin1234` 로 로그인 → 인증 앱 등록(MFA) → **비밀번호 즉시 변경**.
2. 관리자 관리에서 실제 슈퍼관리자 계정 생성 → 그 계정으로 재로그인 → **데모 계정 비활성화**.
3. 수당체계 화면에서 요율·풀 비율이 의도한 값인지 확인(마이그레이션 기본값이 들어가 있음).
4. 상품 화면: 포르투나 구독 120/월, 파트너 멤버십 200/년 이 판매 중인지 확인.
5. 회원가입 1건(`/signup?ref=<루트 초대 코드>`) → 로그인 → Fortuna 앱에서 같은 계정으로 로그인 → 비밀번호 찾기 메일 수신 확인.
6. Vercel → Cron Jobs 탭에서 두 크론이 200 으로 실행됐는지, Logs 에 에러 없는지 확인.
7. Fortuna 앱 `NEXT_PUBLIC_SIGNUP_URL` 을 포털 가입 주소로 변경.

## 4. 지갑 연결(운영) — 별도 세션
Vercel 환경변수에 지갑 4개 기입 → 재배포 → 관리자 입금내역 "스캔 연동" 카드가 준비됨 → 소액 USDT 1건 입금 → 5분 내 감지·매칭 → 출금 신청→승인→지갑 앱 송금→tx_hash 완료 1건.
끝난 기준: 운영 입금 원장에 실체인 입금 1건 '잔액 반영', 출금 1건 '완료'. 그 뒤에만 회원 공개.

## 롤백·주의
- 마이그레이션은 되돌리기 어려우니 `db push` 전 Supabase 대시보드에서 프로젝트가 비어 있는지 확인.
- `service_role` 키·DB 비밀번호·CRON_SECRET 은 채팅·문서에 적지 않는다.
- 로컬 개발은 그대로 `.env.local`(127.0.0.1) 을 쓴다. 운영 값은 Vercel 에만 둔다.
